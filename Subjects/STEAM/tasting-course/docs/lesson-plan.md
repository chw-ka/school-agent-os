# 教案——AI 小裝置嘗鮮課（60 分鐘）
**小五 · 同一課兩節 · UIFlow 2.0 → Vibe Coding（Gemini）**

---

## 學習目標
1. 使用存取碼將實體裝置連接到雲端 IDE
2. 用 UIFlow 2.0 積木控制畫面和按鈕
3. 在請 AI 生成程式碼之前，先設計好多畫面遊戲的流程
4. 用語音向 Gemini 描述遊戲，並將生成的程式跑在真實裝置上

---

## 上課前準備（老師，學生入座前）
- 所有裝置：已預先刷入 UIFlow 2.0、已連接學校 WiFi
- 裝置開機直接顯示：雲端圖示 + 存取碼——學生毋須任何設定
- 示範裝置已載入完整考反應遊戲（見 `starter/demo_reaction_game.py`）
- 學習單已列印：`docs/handouts/student-card.md`——每人一張
- 投影機：同時開啟 `uiflow2.m5stack.com` + Gemini（`gemini.google.com`）兩個分頁
- 兩節之間：執行 `flash_all.sh --quick` 重設裝置（約 5 分鐘）

---

## 第一階段——引入：考反應遊戲（0–5 分鐘）

**老師示範，學生觀看。**

拿起示範裝置，運行完整的考反應遊戲：
- 畫面顯示：「按 A 開始！」
- 按 BtnA → 畫面倒數 → LED 閃爍 → 「NOW！按 A！」
- 按 BtnA → 畫面顯示：「284ms 👍」（若搶先按則顯示「太早了！」）

問全班：*「你估呢個係點做出來㗎？」*  
收集 2–3 個答案，先不解釋，讓好奇心發酵。

最後揭曉：*「今日你哋都會整一個出來——用 AI 幫你寫。」*

---

## 第二階段——認識裝置（5–17 分鐘）

### 硬件介紹（5–9 分鐘）
展示裝置，逐一介紹：
- **畫面** — 135×240 彩色顯示屏
- **BtnA**（側面，橙色）— 主要輸入
- **BtnB**（正面）— 第二按鈕
- **電源鍵**（頂部）— 按住 2 秒開關機；在 UIFlow 2.0 中亦可作 BtnC 使用
- **LED** — RGB 全彩，可用程式控制
- **WiFi** — 已連接學校網絡（老師預先設定好，同學毋須操作）

### 連接 UIFlow 2.0（9–17 分鐘）
1. 用 USB-C 線連接裝置與電腦
2. 裝置顯示：雲端圖示 + 7 位存取碼（例如 `6 / 1269170`）
3. 開啟 Chrome → `uiflow2.m5stack.com`
4. 按**連接裝置** → 輸入存取碼 → **執行一次**
5. 裝置畫面切換至 UIFlow 標誌 = 連接成功 ✅

> **老師確認：** 逐行巡視，確保所有裝置連接後才繼續。  
> **常見問題：** 若瀏覽器斷線，重新輸入裝置畫面上顯示的新存取碼即可。

## 第三階段——第一個積木：計分器（17–30 分鐘）

**目標：感受「積木 → 裝置即時反應」的循環。一次過學會變數和事件。**

### 改變畫面文字（17–21 分鐘）
1. 找 **硬件 → 顯示 → Label → 設定文字**
2. 拖入 `On Start` 積木
3. 輸入自己的名字 → 按 ▶ **執行**
4. 名字即時出現在裝置畫面上！

### 製作計分器（21–30 分鐘）

跟著投影機一起砌：

```
變數：score = 0

On Start：
  設定 Label 文字 = score

當 BtnA 被按下：
  score 加 1
  設定 Label 文字 = score

當 BtnB 被按下：
  score 設為 0
  設定 Label 文字 = score
```

- 執行 → 按 BtnA 不停 → 數字上升
- 按 BtnB → 歸零

> *「BtnA 加分，BtnB reset。係咪好熟悉？其實每個遊戲都係咁嘅原理。」*

**快速挑戰（如有時間）：** 當分數超過 5 分時，能否讓 LED 轉色？

## 第四階段——Vibe Coding：製作考反應遊戲（30–58 分鐘）

**這是課堂核心，可彈性調整時間。**

### 4a — 介紹概念（30–35 分鐘）

在投影機顯示 Gemini 分頁。

*「你哋啱啱用積木砌咗一個計分器。但如果個遊戲複雜少少，積木會越砌越多，越難睇。所以我哋可以唔可以叫 AI 幫手寫？」*

*「但係——AI 唔係魔法。你要解釋清楚你想要咩，佢先至識做。今日我哋用語音輸入，直接同 Gemini 講。」*

重點框架：**先設計，再叫 AI。** 如果你自己都唔知想要咩，AI 只會生出垃圾。

同時介紹 MicroPython：UIFlow 2.0 可以切換至「Python 模式」——積木背後其實係文字程式碼。AI 生成的程式碼就係用呢個模式貼入去。

### 4b — 遊戲設計：填寫學習單（35–45 分鐘）

派發學習單。學生填寫**遊戲設計表**——每個畫面顯示甚麼、每個按鈕做甚麼。

先在黑板一起過（老師畫圖）：

| 畫面 | 顯示內容 | 按鈕動作 | 下一畫面 |
|------|---------|---------|---------|
| 開始 | 「按 A 開始！」 | BtnA → 開始 | 等待 |
| 等待 | 「準備好…」 | （等待隨機時間，甚麼都不做）| GO！ |
| GO！ | 「NOW！按 A！」+ LED 閃 | BtnA → 記錄時間 | 結果 |
| 結果 | 反應時間（毫秒）| BtnA → 再玩 | 開始 |
| 太早了 | 「太早了！」 | BtnA → 再試 | 開始 |

學生自行填寫，可以有自己的版本（文字、顏色、訊息）。

> *「填完之後，你就係個遊戲設計師喇。你已經知道每一頁係點——依家叫 AI 幫你寫出嚟。」*

### 4c — 語音告訴 Gemini（45–52 分鐘）

先由老師在投影機示範：

1. 開啟 Gemini → 按麥克風圖示（語音輸入）
2. 說（可用廣東話或英文）：

> *「幫我用 UIFlow 2.0 MicroPython 為 M5StickS3 寫一個考反應遊戲。  
> 畫面一：顯示「按 A 開始」。  
> 按 BtnA 後，等待一個隨機時間（1 至 3 秒），然後 LED 閃爍，顯示「NOW！按 A！」。  
> 記錄玩家按 BtnA 的速度，用毫秒顯示。  
> 若在等待期間按下，顯示「太早了！」。  
> BtnB 重設遊戲。」*

3. 複製 Gemini 生成的程式碼
4. 在 UIFlow 2.0 → 切換至 **Python 模式**（右上角切換按鈕）
5. 貼上 → ▶ 執行 → 在裝置上測試！

之後讓學生自己做，鼓勵他們按照自己填好的學習單描述遊戲。

> **Gemini 常見問題：**
> - 程式使用 M5StickS3 上不存在的庫 → 告訴 Gemini：*「請只使用 UIFlow 2.0 MicroPython 的 M5StickS3 API」*
> - 缺少 import → 請 Gemini 修正：*「我遇到這個錯誤：[貼上錯誤訊息]，請幫我修復。」*
> - 按鈕名稱錯誤 → UIFlow 2.0 使用 `BtnA`、`BtnB`、`BtnPWR`

### 4d — 執行、測試、改進（52–58 分鐘）

學生執行遊戲，與旁邊的同學互相測試。

鼓勵迭代：*「如果唔啱，你點同 Gemini 講？」* → 他們重新用語音描述具體問題。

## 第五階段——總結 + 小智獎勵（58–60 分鐘）

邀請 1–2 位同學舉起裝置，用一句說話描述自己的遊戲。

總結：*「你哋今日唔係學寫程式——你哋學咗點樣同 AI 溝通，然後 AI 幫你整出真實嘅嘢。呢個係 vibe coding。」*

**下次預告：**  
*「如果你哋個遊戲本身都可以問 AI 問題——例如唔係你問 Gemini 幫你寫，係個 gadget 直接問 DeepSeek——咁會係咩感覺？下次。」*

---

## 小智獎勵——英語對話練習

**提早完成第四階段的同學適用。** 老師處理刷機，學生只需持著裝置。

```bash
# 老師在電腦執行（每次一部裝置）：
./m5sticks3-clone/scripts/flash_xiaozhi.sh
# 重新開機後，小智即時啟動（WiFi 已存於 NVS 分區）
```

學生體驗：
- 插上 USB-C → 裝置醒來 → 說「Hello！」
- 小智用英文（及廣東話／普通話）回應
- 學生可自由對話、問英文生字、叫佢講笑話

教學亮點：
- 同一部裝置，截然不同的「性格」→ *「原來係韌體決定佢識做咩」*
- 學生毋須任何設定，老師約 5 秒完成刷機
- 輕鬆、無壓力的英語對話練習環境

**第二節前還原 UIFlow 2.0：**
```bash
./m5sticks3-clone/scripts/flash_all.sh --quick
```
