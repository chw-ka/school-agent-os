## How CloudSAMS import/export actually works (critical mechanism — read first)

Source: `cloudsams-manuals/ASR/Files/Module/AUM/AUM ASR_C.pdf`, §2.2.4–2.2.5 (p.143–148).

This changes the shape of Phase 2 (Extraction Scripts):

1. **You cannot hand-build an import file from scratch.** The authoritative template must come from CloudSAMS's own **匯出資料 (Export Data)** function first — it embeds a **整批號碼 (batch number)** in the file. On import, CloudSAMS checks that this batch number matches the file name and that the batch was actually generated by *this system's* export. A hand-crafted file with the right column headers will still be rejected if the batch number doesn't match a real prior export.
   - **Practical flow**: Export current (even empty) data for the target class/subject/term → get the real template with correct headers + embedded batch number → fill in values (via script) → re-import under the **same, unmodified file name**.
2. **Export is encrypted.** Clicking 匯出 prompts for a password (self-set, entered twice); output is a password-protected `.zip`. Recipient must decrypt with 7-Zip/WinRAR before editing.
3. **Format constraints**:
   - Scores file (積分與等級): Excel or ZIP. If ZIP, max **10** Excel files inside.
   - Other data (其他資料 — awards, attendance, overall comments, conduct, other-assessment): must be ZIP, max **12** Excel files inside.
   - Excel export errors out if total columns exceed **255** (system will ask you to narrow the selection criteria).
4. **Column names and order must match** `[S-ASR10-01] 學生成績 > 數據輸入 > 其他考績` exactly, or the whole file is rejected with a field-level error report.
5. **All-or-nothing per file**: "如學生紀錄中出現無效資料，所有學生的紀錄將不會被匯入" — if *any* student record in the file is invalid, **none** of the records in that file import. Validation includes: student registration number must exist, score must not exceed the subject's max, grade must match the grade-conversion table.
6. **Precondition**: 考績綱要 (assessment scheme) must be confirmed (**確定綱要**, under 學生成績 > 設定 > 確定綱要) before either export or import will work for a given term. This is *not yet done* for 2026-27 Term 1 on the live system as of 2026-07-05 (see below).
7. Scores are rounded to the valid number of decimal places automatically on import.
8. If a subject/term's data is locked via **數據合併 > 數據整合** (data consolidation lock), it can't be re-imported until unlocked.

**Implication for Phase 2 scripts**: `export_scores.py` etc. can't just emit a CSV/XLS in a vacuum — the realistic pipeline is *export template from CloudSAMS → script fills in values → re-import same file*, OR write directly against whatever the exported template's column schema turns out to be (needs one real export to capture headers, done locally, never committed).

## ANP (獎懲資料 / Awards & Discipline) — no bulk file import

Source: `cloudsams-manuals/ANP/Files/Module/AUM/AUM ANP_C.pdf` (153 pages, read in full for import/export mechanics).

**Key finding: there is no Excel/CSV bulk import for award/punishment records.** The only bulk mechanism is UI-driven **整批處理 (Batch Processing)**, §2.3.2 (p.53–63):
1. Search for a group of students by criteria (class, etc.) → checkbox-select the matching ones.
2. Click 新增獎勵/新增懲罰 (Add Award/Add Punishment) → fill in **one shared record** (date, event text EN/ZH, remarks, etc.) that gets applied to all selected students.
3. A "分配 (Assign)" popup lets you push the *same* field values across multiple selected students in one shot — but every student still gets the identical text/values from that one popup action.
4. There's also 依個別學生 (per-student edit) for one-off entries, and edit paths driven off ECA activities/events or attendance records (a punishment auto-created from an absence, etc.) — none of these are file-upload based either.

**Implication**: Migrating years of legacy award/merit records (`tblStudentAward`, `tblStudentReward`) can't be a spreadsheet import like Academic Results. Realistic options:
- Group legacy records by identical (award-type, date-range, reason-text) and drive the batch-processing UI via browser automation, one group at a time — feasible but nothing like a clean file import.
- Enter only a curated/summarized subset (e.g. current year forward) and treat deep history as out of scope (aligns with existing Phase 6 "nice-to-have" framing for historical archive).
- Ask EDB support directly whether an API exists — not documented in this manual.

**Also relevant**: ANP is where the **conduct point system** (操行分制度 / 功過制) actually lives — see the Conduct section below.

## ATT (學生出席資料 / Attendance) — genuine downloadable templates, more migration-friendly

Source: `cloudsams-manuals/ATT/Files/Module/AUM/AUM ATT_C.pdf` (86 pages), §2.3 (p.29–38).

Unlike ASR, **you don't need to export existing data first to get a template** — go straight to 學生出席資料 → 輸入資料 → 輸入, and the page has two direct download links:
- **下載輸入出席資料範本** (download the blank input template)
- **下載輸入出席資料規格表** (download the field spec sheet)

No password encryption on this import path (contrast with ASR's encrypted export and STA's encrypted export below). Key behavior:
- Import **replaces** existing attendance records outright ("最新匯入的資料檔案將會取代現存紀錄") — this is a full overwrite per the imported scope, not a merge. Re-importing needs care around scope (which dates/classes are in the file).
- If the import changes records tied to award/punishment consequences (e.g. an absence that triggered a demerit in ANP), the related ANP record gets deleted automatically — a cross-module side effect to watch for during test migration (Phase 3).
- Import gives a summary: total / no-warning / warning / error record counts, plus a viewable error report.
- Preconditions: school calendar (校曆編修, in 學校管理) must be set for the year, plus 出席紀錄參數 (attendance parameters) and 特別出席日 (special attendance days) already configured for that year.

**This is the best-case module so far for Phase 2** — a real blank template + spec sheet, no chicken-and-egg export-first requirement.

## STA (課外活動 / ECA) — export/import exists, similar shape to ASR

Source: `cloudsams-manuals/STA/Files/Module/AUM/AUM STA_C.pdf` (130 pages), §2.7–2.8 (p.52–58).

- **匯出 (Export)**, p.55: select one or more ECA activities → 匯出 → set + confirm a password → data is encrypted and delivered as a **self-extracting .exe** (not .zip like ASR/ANP — different format, worth double-checking your OS/antivirus can run it, since self-extracting .exe from a browser download may get flagged).
- **匯入 (Import)**, p.57–58: prerequisite is "must download and use the system's own 學生課外活動資料表範本 (student ECA data template)" to build the import file — implies a template-first flow similar to ASR, though this manual doesn't explicitly spell out a batch-number check like ASR's. Import validates the spreadsheet, shows an error report if problems found, or an [A]/[R] accept/reject confirmation screen per record if clean (same UX pattern as ASR).

**P1 priority** (ECA/service posts) — mechanically workable, similar effort profile to Academic Results.

## Conduct (操行) — real structural gap, not just a mapping problem

This took the most digging. Conduct data does **not** have its own independent 5-dimension entry/import screen anywhere in ASR. Instead:

1. **ASR's "操行" settings** (§2.1.8, p.90) only configures the *grade conversion table* and consolidation method — it's settings, not data entry.
2. **Actual conduct scores live in the ANP (獎懲資料) module**, under whichever point system the school has configured — either **功過制 (merit/demerit-count system)** or **操行分制度 (conduct-point system)** — both are point-accumulation models, configured with up to **5 merit levels and 5 demerit levels** (ANP manual, p.131 note).
3. To get conduct onto the report card, ASR's **數據輸入 → 其他考績** screen (§2.2.3, p.130–133) has a **[從獎懲資料模組複製] (Copy from Awards/Discipline module)** button that pulls ANP's *already-consolidated* (數據合併 done) point totals into ASR, where a user can review/override in a "修改" column before saving.

**This means CloudSAMS's conduct model is fundamentally point-accumulation (tally of merits/demerits by level), not "5 independent per-term dimension scores"** the way `tblStudentConduct` is structured. This is exactly the kind of gap the plan's risk table already anticipated ("CloudSAMS doesn't support some custom fields e.g. 5 conduct dimensions — Medium likelihood, High impact"). **This is now confirmed, not just a risk** — needs a Phase 1 decision with CM/ES/PY on one of:
- Map each of the 5 legacy dimensions to a merit/demerit level category in ANP's point system (lossy — accumulation math is different from independent 0–5 or letter-grade dimension scores).
- Use ASR's free-text "其他考績" (text-evaluated, not grade-based) to preserve the 5 dimensions as descriptive text per student instead of structured scores.
- Drop structured conduct dimensions from CloudSAMS entirely and keep them in a legacy reference export only (matches "Drop" option in the plan's gap-decision framework).

No bulk import path exists for conduct either way — it inherits ANP's UI-only batch-processing constraint.

## Comments — two different things, two different mechanisms

Source: ASR manual §2.2.2 (p.125–129), plus the code-table export found earlier.

1. **科目評語/科目備註 (Subject comments/remarks)** — entered per student via a dedicated grid screen: 學生成績 → 數據輸入 → 科目評語. User searches by class+subject (or subject-group, or cross-class subject), then gets a table with one row per student and a free-text box per row — filled by typing a code + Enter (auto-fills from the code table), picking from a popup list, or typing directly. Language mode (English-only / Chinese-only / bilingual) is configured separately in 班級考績設定. **No bulk file import for this screen** — the general export/import (2.2.4/2.2.5) explicitly lists what it covers (積分與等級、獎懲資料、缺席紀錄、整體評語、操行、其他考績) and 科目評語/科目備註 is **not** in that list. Max 9 subject-remark slots per grade level; subject comment text itself capped at 60 characters (matches the code-table limit found earlier).
2. **整體評語 (Overall Comments — this is what the legacy plan's "class teacher comments" maps to)** — this one **is** covered by the general bulk export/import alongside scores (same batch-number/filename/encryption mechanism as §2.2.4–2.2.5). 700-character limit (found earlier via the code-table manual pages). **Still to verify live**: whether CloudSAMS's overall-comment field supports the legacy's "4 slots per term" structure, or is a single field — check once logged back in.

**Implication**: subject-level comments will likely need either manual re-entry through the grid UI (feasible if volume is low, painful at scale) or browser automation against that grid; overall/class-teacher comments can ride the same bulk pipeline as scores.

## Student/subject enrollment — partially automatic, with a real bulk-import fallback

Source: STU (學生資料) manual §2.9 (Registration, p.89–105) and §2.7 (Subject Setting, p.78–90).

**How students normally enter CloudSAMS** (§2.9, "註冊/Registration"):
- **中一派位 (S1 Central Allocation)** and **小一派位 (P1 Central Allocation)** — new intake each year arrives automatically via EDB's central allocation result, pre-populating student details for the school to confirm/accept (取錄示標) rather than type in from scratch. Prerequisite: the central allocation (CA) result must already be imported into the **SPA (學位分配/Place Allocation)** module — that's an EDB-fed process, not something the school builds a file for.
- **中四學位安排 (S4 Placement)** — same pattern, for schools with non-continuous S3→S4 flows.
- **個別註冊 (Individual Registration)** and **整批註冊 (Batch Registration)** — fully manual, one student typed in at a time (整批註冊 just means doing several individual entries in one session, not a file upload).
- **註冊檔案上載 (Registration File Upload)**, §2.9.6 (p.103–105) — **this is the real bulk-import path**: download a blank Excel template, fill in new student records, upload. All-or-nothing validation (whole file rejected on any error, with a viewable error report). **Recommended limit: under 100 student records per file** — for migrating ~1000 continuing students this means chunking into 10+ files. One row per student.

**Confirmed live 2026-07-05**: ran 學生資料 → 學生概況 → 搜尋學生 with no filters (all levels, current 2025 school year) — returned a full multi-page roster (15 pages × 50/page) of real, currently-enrolled students, not just new intake. **The continuing student roster is already fully populated in CloudSAMS.** No bulk registration upload needed for enrollment — the plan's original assumption holds. (No student names/IDs recorded here or anywhere in this doc, per data-privacy policy — aggregate fact only.)

**Subject enrollment**: §2.7.4 檔案上載 (p.90) — a separate Excel upload specifically for cross-class subject groupings, sourced from the "學生選科程式" (Student Subject Selection Program) tool's own export format. Prerequisite: the cross-class subject groups must already be set up in 學校管理 (School Management) with matching codes before this upload will attach students to them correctly.
